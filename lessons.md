# Lessons

- [1x] /goal briefs: Jack ALWAYS wants the verbose, expansive, targeted brief written to `.claude/goals/<date>-<slug>.md` with a short self-bootstrapping pointer pasted into /goal — file-backed is the DEFAULT; never trim a brief to squeeze under the 4,000-char cap (2026-07-28; whats-next/goal-maker/bhag command docs rewritten to match).
- [1x] PyPI publishing is handled via GitHub Actions trusted publishing. NEVER use twine to upload directly. Create a GitHub release and PyPI pulls it automatically.
- [2x] Always run tests with `uv run python -m pytest` (NOT bare `python -m pytest`). Dev deps (pytest) are in `[dependency-groups] dev` which uv auto-includes. System/conda Python won't have project deps.
- [1x] When the user picks a "PR first, then release"-style path, treat the PR as a REVIEW GATE — open it and STOP. Do not self-merge into master without an explicit, separate go-ahead. The auto-mode classifier will (correctly) block the merge otherwise. Build the whole thing on the branch, push, open the PR, then ask before merging.
- [1x] Frontend polish (Tailwind class tweaks in JS template literals) can break unit tests that assert on EXACT rendered class strings (e.g. `test_web_js_swap_ui.py` asserts `whitespace-nowrap">4m 32s`). Adding `tabular-nums` etc. shifts those substrings. Run the full suite before any release and update the brittle assertions to the new intended markup — don't revert the improvement.
- [1x] When adding shell operators to SHELL_OPERATOR_RE, enumerate ALL operators including redirection (>, >>, <) and newlines (\n). Missing even one creates a bypass where safe-prefix commands can write to arbitrary files.
- [1x] SAFE_PREFIXES entries that also exist in SAFE_EXACT must have a trailing space (e.g. "env " not "env") — otherwise startswith() matches unintended commands like envsubst, lsblk, etc.
- [1x] After changing install/uninstall logic, ALWAYS verify the live hook path in ~/.claude/settings.json points to the right python and script. Stale non-editable installs mean your code changes are invisible.
- [1x] When designing LLM prompts for the gatekeeper, ALWAYS require a "reason" field in both allow AND deny JSON responses. Without it, logs are useless for auditing decisions.
- [1x] Avoid double-logging: raw LLM response goes to log_debug() only, parsed DECISION line goes to log(). Users only see the main log — put all useful info (method, reason, timing) on the DECISION line.
- [2x] The installed jacked tool may not be editable or current: `jacked upgrade` reinstalls non-editable from PyPI and silently replaces an `--editable` dev install. Before attributing behavior to repo code, check what the tool env imports from a neutral cwd: `cd /tmp && ~/.local/share/uv/tools/claude-jacked/bin/python -c 'import jacked; print(jacked.__file__, jacked.__version__)'` (a cwd inside the repo shadows the tool env and lies). Verify repo code through `uv run python -m jacked ...`, not the PATH binary.
- [3x] For any non-trivial implementation, default to the full jack-it-up cycle: brainstorm, HTML plan, plan review, subagent execution, implementation review, and proof. If Jack explicitly asks for a faster/modified cycle, compress it with parallel ownership and one consolidated review instead of forcing the long per-task loop, but never skip the final full test, security, and release gates. Auto-mode alone is not permission to compress the cycle.
- [1x] When a function returns "success" (like True) as a skip condition (e.g. "nothing to do"), callers must not assume all side effects happened. Trace what DOESN'T get set on the skip path. Burned time on heal loop thinking refresh_account_token returning True meant validation_status was updated — it wasn't.
- [1x] Verify which version is actually running (`/api/version` plus the uv tool env from a neutral cwd) before attributing a regression to a release. When touching any polling or retry system, audit every refire caller for a rate floor in the same PR; a refire path without one is a latent runaway.
- [1x] Rate limiters must never reset themselves on failure: fetch_usage's 429 handler zeroed `last_fetched_at` AND rotated the CC refresh token to dodge the per-token limit (243 rotations/4.5h). A 429 response must slow the caller down, never speed it up or rotate credentials at high frequency.
- [1x] VERIFY THE BRANCH IS CURRENT before doing any work, and AGAIN before committing/PR. On 2026-06-18 I built an entire Windows fix on `jack_20260612_1` which was 42 commits / 6 minor versions behind origin/master — only caught because the user noticed. Always `git fetch` + `git rev-list --left-right --count origin/master...HEAD` at session start; if behind, branch fresh from origin/master (or rebase) BEFORE editing. cli.py had diverged ~250 lines; a patch from a stale base is a guaranteed mess.
- [1x] lessons.md ALWAYS gets committed into the main codebase — never leave it as a local-only modified file. After appending a lesson, commit it (and push) so future sessions and other machines actually see it. It's tracked, not ignored.
- [1x] Before root-causing a "missing" UI element, CONFIRM it's actually absent vs merely hidden — Windows parks new tray icons in the notification-area overflow (the ^ chevron) by default. Check creation logs first: the tray logs "Service ready (pid=…)" only AFTER pystray's icon appears. On 2026-06-19 I blamed the uv-trampoline (uv venv on anaconda base → pythonw spawns a child interpreter) for a missing jacked tray icon and wrote + tested a whole autostart-rewrite — but the original service's log showed "Service ready", proving the icon WAS created; it was just in the overflow. Burned a full implementation cycle on a non-bug. Verify the failure mode before theorizing + coding a fix. (Also: stop killing/restarting a user's WORKING service to chase a cosmetic issue — I broke the live dashboard several times mid-diagnosis.)
- [1x] When the user asks to SURFACE/SHOW data ("let me see the usage for those models"), show it universally — do NOT add a cleverness threshold/filter that hides some of it unless they asked. On the per-model usage feature (2026-07-03) I gated the inline bar behind "only if the model is the active constraint OR >=71% used" — the user immediately noticed two accounts weren't showing their model and said "they should all show it." The gate was unrequested scope that directly contradicted the ask. Show everything the payload reports; if you think a filter improves it, propose it, don't silently impose it.
- [2x] A bare `: ` (colon+space) inside an unquoted YAML scalar is invalid YAML — struck TWICE on 2026-07-10: a workflow `run:` line (`--only-binary=:all: uv`; GitHub reports it only as a 0-second failed run named by file path, zero jobs, nothing in `gh pr checks`) and a SKILL.md frontmatter description (`...one shot: extracts...`; the one skill of 25 that failed to parse). ALWAYS yaml-parse any hand-authored YAML (workflows, skill/command/agent frontmatter) before shipping: python -c "import yaml; yaml.safe_load(...)". Fixes: `run: |` block scalars for commands; quote frontmatter values containing colons.
- [1x] Don't call a UI/layout change "good enough" off one screenshot — judge content DENSITY at the real target width. On 2026-06-19 I put the account cards in a 2-col grid still capped to the old 1024px width, so each card was ~505px; the dense cards (name+pills row, email/sub/usage-meta row, usage bars) were cramped and cluttered and the user rightly hated it. Fix: widen the wrapper to use the screen (max-w-[1700px]) and reflow with `grid-template-columns: repeat(auto-fit, minmax(min(600px,100%), 1fr))` so a 2nd column appears ONLY when each card can be a comfortable width (~800px here), capped at 2 by the wrapper max-width. Corollaries: a flex `main` needs `min-w-0` to shrink, and wide data tables need a wrapper with `overflow-x-auto` or they force page-wide horizontal cutoff. Look at it critically (is there breathing room?), don't just confirm it rendered.
- [1x] Don't run the full ~7-min pytest suite mid-iteration - run the affected-test subset (seconds) while iterating and the FULL suite exactly once, as the final commit/release gate. And never chain a slow gate in front of an already-finished result (a codex verify JSON sat ready 5 min while pytest blocked the reveal); run them as independently observable tasks. (Jack, 2026-08-20: "no way it takes 10 mins / that's nuts")
- [1x] When Jack specifies a runtime model, especially Codex-Spark for speed, verify the active runtime before continuing. Never substitute another GPT-5-family model or imply the requested model is active; if hot-swapping is unavailable, stop and ask Jack to relaunch or switch the session.
- [3x] Before PUBLISHING any service-lifecycle change, run the REAL `jacked upgrade` from the previous PyPI version on the target machine (install the built wheel with a bumped version into the tool env, then upgrade to it), and prove ONE launchd-owned tray, one listener, no crash loop, `launchctl print` naming the new generation. STRUCK A THIRD TIME 2026-09-05: v0.101.0 shipped, then the first real `jacked upgrade` on this Mac left the launchd job unloaded and a manual tray (bootout/bootstrap EIO race in the install step, restart falling back to a detached spawn). Yesterday's strike (Homebrew trust check) was the same lesson. The mixed-generation upgrade is the release gate, not a post-release check. Graduate this with /learn.
- [1x] A security check that decides whether the service may BOOT must be calibrated against real machine layouts, not fixtures: enumerate the common interpreter homes (uv-managed, Homebrew, miniconda cask, pyenv, system) and their real modes/owners before rejecting a permission pattern. Group-writable by a root-equivalent group (macOS `admin`, Linux `sudo`/`wheel`) is not a privilege boundary. Never let a refusal escape as a traceback: record the reason where `jacked service status` can print it.
- [1x] Tests must NEVER reach the real machine: the service conftest isolated CLAUDE_DIR but not Path.home(), so `service restart` and status tests spawned a real detached tray from the repo venv and shelled out to the real launchctl during a routine `pytest tests/unit/service` run (2026-09-04). tests/conftest.py now carries a tripwire (`_no_real_service_processes`, opt out with `@pytest.mark.real_process`) and the service conftest patches Path.home. When a test needs a subprocess, patch it explicitly; when you see an unexplained service start mid-session, suspect the suite first.
- [1x] A credential SWITCH is not done when the store changed; it is done when a RUNNING Claude Code session follows it. Claude Code keeps its OAuth token in memory and re-reads the store only when the `oauthAccount` identity in `~/.claude.json` changes; a Keychain write alone is invisible to every open session (2026-09-04: the 09-03 transaction-engine rewrite, b6391c7, dropped the `~/.claude.json` identity write, so the dashboard said switched while all 18 open sessions kept the old account; 0.94.1 still wrote it and worked). Any change to the switch path must end with the pty probe in the plan doc: start an interactive `claude`, switch, read `/status` inside that session. Store-level asserts (Keychain, mirror file) are prep, never the proof.
- [1x] Claude Code REFRESHES tokens from the account it holds in memory and writes the result straight into the shared Keychain item with NO `_jackedAccountId` stamp (2026-09-05: 18 open sessions across 4 accounts; a stale jackusc session refreshed and silently replaced the chosen raiderpartners authority twice in five minutes; the tell in the log is `Credential schema drift ... refreshTokenExpiresAt`). Any design for account switching must assume the authority can be rewritten by a foreign writer at any token expiry: adopt the rotated tokens for the identified account FIRST (a single-use refresh token overwritten without import kills that account with invalid_grant, which is how account 7 died), then reassert the desired default. And a switch outcome that every production build produces (`observed_target_unfenced` on macOS) must run the same bookkeeping as a committed one; gating residency on `committed` silently disabled it everywhere.
- [1x] launchd `ProcessType: Background` is CPU/IO-THROTTLED by design (launchd.plist(5): limits applied "to prevent them from disrupting the user experience"). On a loaded Mac (load avg 165 during a VM build) the jacked tray under Background priority 4 was still importing Python 2 minutes into its 90s readiness window, while the same binary from a shell (priority 31+) booted in 2s; every launchd boot then tripped the start-failure breaker. A user-facing agent with a readiness budget must be `Interactive` (2026-09-05). Diagnostic tell: `ps -o etime,cputime` shows seconds of CPU over minutes of wall time, and `ps -o pri` shows a single-digit priority.
- [1x] jacked's 30-minute background refresh rotates the Claude Code refresh token of every NON-active account ("Account 1: cc token refreshed"). A refresh token is single-use, so any open Claude Code session still holding that account has a dead lineage the moment its access token expires and demands `/login` (the 2026-09-05 "log in again in every session" symptom). The skip must cover every account a live session holds (the session tracker knows), not just the active one. Not yet fixed as of v0.101.0.
- [1x] `launchctl bootout` is ASYNCHRONOUS: it returns at once while the job name stays registered until the old process finishes draining (`launchctl print <domain>` keeps returning 0 for seconds; a tray shutting uvicorn down takes 5-12s). A `bootstrap` inside that window fails with EIO (exit 5) and so does any rollback bootstrap, leaving the job UNLOADED. Always poll `launchctl print` until exit 113 before bootstrapping, and retry an EIO bootstrap once the name is free (2026-09-05, proven on a throwaway agent).
- [1x] `launchctl kickstart -k` and `bootout` BLOCK while launchd waits for the running process to exit; a tray mid-shutdown drains 12s+ under load (uvicorn graceful then force-exit), so a flat 15s launchctl timeout turned a healthy handoff into `TimeoutExpired`, and the upgrade transaction rolled back a build that was already coming up (2026-09-05, first real 0.102.0 upgrade). Two rules: size lifecycle-waiting supervisor calls to the handoff budget, and after a timed-out restart judge by the OUTCOME (did the exact generation become ready) before refusing. A healthy handoff measures 2s; the lesson is about load, not the happy path.

- [1x] Review loops need a CONVERGENCE rule, not a "keep going" rule (2026-09-05, hank-os-c8 report: 12 rounds, ~200 agents, ~42M tokens, 9 full suites, ~30h for 6 real bugs; ~10 findings were regressions from the previous round's fixes, ~50 were docstring polish, 0 of ~200 refuter verdicts changed a decision). Six texts each said "never stop on success / fix everything you find / answer is always yes" and together had no fixed point. Fixed in 0.103.0: scope line + `introduced_by_branch` on every finding, fix-vs-file buckets, stop when a wave yields no branch-introduced defect, cap 2, third wave = split the PR. Any new drive-until-done text must name its stop condition, and "new work surfaced" is never a stop-blocker for a REVIEW loop.
