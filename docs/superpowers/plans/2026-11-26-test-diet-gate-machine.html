A gate machine can be a host that serves production. The driver must never stop, signal or disturb a process that it did not start, and must never write or delete outside its own folder. Each rule below that has the word "never" has a test.
On hold. Do not build from this document. The review found nine open defects in it, and there is a second mechanism that this plan did not compare. The section "State of this plan" has both.

State of this plan (2026-11-26)

The owner approved a gate on a different machine as a part of jacked. This plan builds it as a job runner over SSH. The second review read the plan and found that most of its open defects are in the parts that make it a job runner: the queue, the lock, the cancel, the run that a session leaves.

The open defects

  1. --detach returns 0, and a failed fetch returns the exit code of the gate. Both give a verdict that no record holds. Both must return 75.
  2. "A member of the lock is alive" has no mechanism, and a run with no owner has no way out.
  3. The plan gives two different values for the heartbeat and for the retry, and has no state for a run that its client left.
  4. machines gc and machines forget-repo have no driver verb, no rule and no test.
  5. A run verb is not tied to the repository of the caller. One session can cancel the run of a different session.
  6. The key of a shared run is too narrow, the first client cleans up for each client, and there is no state for a cancelled run.
  7. The address of the gate machine can still reach the terminal in the error text of ssh.
  8. collect_pending records a run against the wrong tree, and it puts a network call into seen and history.
  9. Small defects: a pattern that accepts a newline at its end, the state folder of jacked, a command line with backslashes, a repository with two root commits, processor time of children that nobody waited for.

Goal

jacked tests run --on <label> -- "<gate command>" runs a gate on a gate machine over SSH and records it in the local history. The gate runs the commit that was sent, one exclusive gate at a time on that machine, and a lost connection never gives a verdict.

Spec: 2026-11-25-test-diet-design.html, section "A gate on a different machine", and acceptance item "Gate machine".

Tech stack: Python 3.11+ on the local side. The file gate_driver.py runs on the gate machine with Python 3.8 or later and the standard library only, on Linux, macOS and Windows. ssh, scp and git on both sides.

Global constraints

The global constraints of plan A apply. These are added.

  • The driver imports nothing from jacked. It restates the rules of jacked/pid_lockdir.py, jacked/process_identity.py (creation_id, line 187) and jacked/service/process.py, because it cannot import them. Each restated rule names its source in a comment.
  • One grammar for each value that crosses SSH or becomes a part of a path. The local side checks it before it sends. The driver checks it again, because any SSH client can call the driver. RUN: ^[0-9]{8}T[0-9]{6}Z-[0-9a-f]{8}$. SHA: ^[0-9a-f]{40}([0-9a-f]{24})?$. REPO: ^[0-9a-f]{16}$. A number: digits only. A verb: one of a fixed set. A label and an environment key: [A-Za-z0-9._-]+ and ^[A-Za-z_][A-Za-z0-9_]*$.
  • REPO is not a folder name. It is the first 16 hex characters of the SHA-256 of the root commit of the repository.
  • The driver never calls os.kill on Windows, and never signals PID 0, PID 1 or a negative PID. On Windows os.kill stops a process for almost every signal value.
  • A process is its PID and its creation token. A PID with no readable token is "unknown", and unknown never permits a stop.
  • A delete is self-evidencing. cleanup and cancel act only on a folder that is inside root/runs after the path is resolved, is not a link, and holds the marker file that the driver wrote in recv.
  • The gate machine is less trusted than the local machine. Each answer is checked for its type. A tar from it is never extracted. An XML file from it goes through the reader of plan A.
  • The SSH destination and the remote root are never printed and never go into a record. A message names the label.
  • The tests of this plan use LocalTransport: the driver as a child process with a temporary root. No test opens a network connection.

Review focus

  1. A PID that the system used again after a restart of the gate machine or the end of a supervisor. Expected: cancel stops nothing, and a lock whose holder has a different token is stale. Tests in Tasks 2 and 3.
  2. A value that changes the meaning of a command or a path: a RUN of .., a folder name with ;, a have answer of --all, an ssh value that starts with -. Expected: refused on both sides. Tests in Tasks 1 and 4.
  3. The connection drops, the local command is stopped by a tool timeout, or the gate machine restarts. Expected: no record and exit 75 with no exit marker; a later command collects a run that finished; a run with no client does not start. Tests in Tasks 3 and 5.
  4. Two sessions send a gate at the same time, for two repositories or for one commit. Expected: one exclusive gate at a time, the second attaches to a run of the same commit and command, and no session waits with no end. Tests in Tasks 3 and 5.
  5. A wrong or hostile answer from the gate machine: a tar member with a parent path, a link or a device; an exit marker with a wrong type; a log with escape sequences. Expected: nothing is written outside a private local folder, and a wrong type is no verdict. Tests in Task 5.

The README says to use an alias of the SSH configuration as the ssh value, so that the list holds no address.The address stays local.
Root on the gate machineThe driver resolves its own root: ~/.jacked-gate through os.path.expanduser. No path crosses SSH. The root, repos, runs and each run folder have mode 0700, and each file 0600. The driver refuses a root that is a link, that the user does not own, or that group or others can write.A Windows shell does not expand ~, and a path with a space breaks the argument split.
TransportEach step is ssh -a -x -T -o BatchMode=yes -o ClearAllForwardings=yes -- <dest> <python> <driver file> <verb> <values of the grammar>, with the payload on standard input or output. ssh, scp and git come from jacked.findbin.find_bin. Proven on the owner's Windows machine on 2026-11-26: 1 MB of binary standard input arrived with the same SHA-256.A value of the grammar needs no quoting in a POSIX shell or a Windows shell. The gate machine never gets the local SSH agent.
Driver installThe driver file on the gate machine is gate_driver-<first 12 hex of its SHA-256>.py in the remote home. scp sends it to a temporary name; the driver checks its own hash and renames itself. Each run folder records the driver hash.Two jacked builds must not replace each other's driver in the middle of a run.
Sending the commitThe local side makes a temporary ref refs/jacked/gate/<RUN>, makes a bundle of that ref without the commits of the have answer, and deletes the ref. Each element of the have answer must match the SHA grammar, be a commit in the local repository and be an ancestor of the sent commit; if not, it is dropped with one printed line. The elements go to git on standard input. When the gate clone holds the commit, no bundle is sent.A bundle needs a ref name. A have answer of --all must not widen the bundle.
The gate clonerepos/<REPO>.git, bare, with core.autocrlf=false, core.fsmonitor=false and core.hooksPath at the null device. The driver sets GIT_TERMINAL_PROMPT=0 and fetches the bundle into refs/jacked/gate/<RUN>.Nothing of a repository runs on git worktree add.
The gate commandOne command line, in the JSON of start. The driver runs it with /bin/sh -c on POSIX and with cmd.exe /d /s /c on Windows, with the null device as standard input. It sets JACKED_GATE=1 and JACKED_GATE_WORKERS from the list. --setup "CMD" runs first in the same way; a setup that fails gives no gate and exit 75.A new worktree has none of the files that git ignores. The repository says how to provide them.
EnvironmentNo local variable goes to the gate machine by default. --env KEY sends one. A key that starts with JACKED_GATE is refused. No value is printed or recorded.A credential must not reach a less trusted machine by accident.
ContainmentPOSIX: the supervisor starts the gate in a new session, so the gate is a process group whose ID is the PID of its leader. Windows: the driver starts the supervisor with DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_BREAKAWAY_FROM_JOB and stops with an error when the system refuses the breakaway; the supervisor puts the gate in a Job Object with "kill on job close" through ctypes.The children of a gate are a fact of the kernel, not a walk over parent PIDs. Proven on 2026-11-26: with the breakaway flag a process lived after the SSH session ended, and without it the process died.
LivenessThe supervisor writes a heartbeat file each 5 seconds. A run is alive when its heartbeat is newer than 30 seconds by the clock of the gate machine. No PID is probed for liveness.A PID can be used again. A probe with os.kill stops a process on Windows.
Statesqueued, running, done (an exit marker exists), lost (no marker, the heartbeat is stale, no member of the group or the job is alive), orphaned (no marker, the heartbeat is stale, a member is alive: the lock stays).A gate whose supervisor died can still use the machine.
The lockThe folder full-gate.lock. To take it, the supervisor makes a private folder with the holder file (the run, the PID, the creation token, the start time) and renames it to the lock name. To break a stale lock, a waiter renames the lock to a private name, checks that the moved holder file is the one that it judged stale, and deletes it. A supervisor removes the lock only while the holder file names its run. A lock with no holder file is stale after 30 seconds. The answer of status names the holder by its run ID and its start time only.A crash between two steps must not leave a lock that blocks each gate, and two waiters must not both take it.
Which run takes the lock--exclusive. It is the default for kind full. The flag does not change the kind of the record.A short proof run must be able to take the lock and stay a targeted record.
A queued run and its clientEach status call touches the file client of the run. A queued run whose client file is older than 60 seconds does not start and becomes lost, unless it was started with --detach.A session that was stopped must not leave a full gate that starts later with no reader.
The same gate two timesBefore recv, the driver answers find REPO SHA COMMAND_SHA. When a queued or a running run has the three values, run_on attaches to it.Two sessions that gate one commit share one gate.
A stopped local commandBefore start, run_on writes <store>/pending/<RUN>.json (the label, the commit, the command SHA, the JUnit globs). Each later jacked tests run, seen and history collects the pending runs that are done, and prints one line for each. --attach RUN waits for one. --detach returns 0 after start and prints the run ID. An interrupt prints the attach line and leaves the gate alive.A full gate is longer than the limit of a tool call.
Waitingrun_on prints the holder and the time that it has held the lock, one time for each change. --max-wait SECONDS gives up, cancels its own queued run and returns 75. A failed ssh call in the poll (exit 255) is printed and tried again with a delay that grows to 60 seconds; the same flag bounds it.The caller chooses how long it waits. No fixed limit drops a gate.
Reading the answerEach JSON answer is checked for its types: a commit matches the grammar, clean is the value true, an exit code is an integer from 0 to 255 and not a boolean. A wrong type is no verdict: exit 75. The tar of fetch is read as a stream (tarfile.open(mode="r|")); only regular members are read through extractfile, and each is written under a name that the local side makes in a new private folder. The driver adds only regular files (lstat) that resolve inside the worktree, and refuses a JUnit glob that is absolute or has ... The driver decides which JUnit file is fresh, with its own stat snapshot.A tar can write outside its target. Two clocks cannot be compared.
The logfetch RUN log gives the full log. The local side writes it to a private file in the temporary folder, prints its path and its last lines with control characters removed and the run folder path replaced by <run>, and does not put it into the history.The cleanup must not delete the only log of a gate. A log holds test output, which the history never holds.
Processor timeThe supervisor measures the processor time of the gate: the difference of RUSAGE_CHILDREN on POSIX, the accounting of the Job Object on Windows. It is in exit.json.The processor time is the figure that the load changes least.
Leftoversprobe reports the free disk space and the number and size of the run folders. jacked tests machines gc LABEL lists and removes the runs in a final state and prints each one. jacked tests machines forget-repo LABEL removes the gate clone of the present repository.A full disk on a host that serves production is an outage.
