Goal

Ship a gate recorder (jacked tests) and a skill (/test-diet) in claude-jacked, for Claude Code and for Codex. The recorder measures each gate and can run a gate on a different machine. The skill uses those records to make a repository's test suite smaller and faster on a branch, with evidence for each cut, and opens a pull request.

Spec: 2026-11-25-test-diet-design.html (approved by the owner on 2026-11-26). Research: 2026-11-25-test-suite-diet-research.html. The executor reads both.

Tech stack: Python 3.10+, the standard library only for the new package, click for the command group, pytest for the tests. No new dependency.

Architecture

One new package, jacked/testdiet/, holds the mechanical work: it reads JUnit XML, gives each tree an identity, keeps a local history, compares test IDs with a ledger, and sends a gate to a gate machine over SSH. One new skill directory holds the judgment as guidance for a model. The skill calls the commands. The commands never decide that a test is junk.

Global constraints

Each task's requirements include this section.

  • Standard library only in jacked/testdiet/. gate_driver.py imports nothing from jacked and runs on Python 3.8 or later, on Linux, macOS and Windows.
  • No module name starts with test_ in the package (pytest collects test_*.py).
  • The history holds IDs, numbers and states only. No failure text, no test output, no log text. It is in the common git directory of the clone and git never commits it.
  • A value that a file does not hold stays empty (None in Python, null in JSON). It is never zero.
  • jacked tests run returns the exit code of the command that it wraps. A recorder error never changes that code. A run with no verdict returns 75.
  • Times of two machines are never compared.
  • No committed file holds a host name, an address or a user name of a machine. Tests and documents use the label shed and the address gate.example.
  • No arbitrary threshold decides a verdict. A command prints numbers. It does not call a test slow, junk or flaky.
  • The skill text is guidance for a model. No point tables, no regular expressions that give a verdict. A name or a text pattern only nominates a test.
  • The new skill has no <!-- ENGINE --> marker and has disable-model-invocation: true.
  • Documentation, docstrings and user-visible messages are in ASD-STE100. No em-dash in them.
  • Sample JUnit files come from real runs. Nobody writes one by hand.
  • A test name in this plan is a requirement. The test asserts what its name says, with the values of the rules of its task. A task can add tests. It does not drop one.
  • The suite runs on Linux, macOS and Windows in hosted CI. A value that a system does not give (the load average and the processor time of child processes on Windows) is empty there.
  • Tests: uv run python -m pytest <files>, never bare python -m pytest. Each task runs its own test files plus grep -rl <changed module or directory name> tests/. The full suite runs one time, in Task 14. Each task reports --durations=10 of its new test files.
  • Process rule, verbatim in each brief: NEVER pkill -f / killall a generic pattern (pytest, python, node, a server name) on this machine; stop only processes you started, by PID.
  • Load: run uptime before each test run. Above a load of 15 on this machine, run the targeted files with no parallel workers and say so.

Review focus

The inputs that the spec implies and that are most likely to break the tool for a person. Each line has a test in the task that owns the code.

  1. The gate writes no JUnit file, an old one, or half of one (the runner was killed). Expected: the exit code of the gate comes back unchanged, the record has no test data, and an old file is never recorded as this run. Tests in Task 3.
  2. The tree changes while the gate runs, or the tree has changes that are not committed. Expected: seen never says that such a tree passed because its commit passed. Tests in Tasks 2 and 3.
  3. Several sessions finish a gate in the same second. Expected: each record is complete and readable. Test in Task 2.
  4. pytest IDs from a JUnit file and from a collection list differ in form for a test in a class, a parametrized test and a nested class. Expected: one normalized ID. Test in Task 1.
  5. The connection to the gate machine drops, the gate machine restarts, or a lock holder dies. Expected: no record and exit code 75 for a run with no exit marker, and a dead holder does not block the next gate. Tests in Task 7.

Rules. The child inherits standard output and standard error. The tree identity is read before the child starts and again after it ends; when they differ, tree_changed is true. Outside a git repository, run runs the command, prints one line, records nothing and returns the exit code. A child that a signal stops gives 128 plus the signal number. A command that cannot start gives 127. seen returns a run only when: kind is full, exit code is 0, tree_changed is false, and the tree hash is equal. The notice goes to standard error after the child ends, and says how many earlier records hold the same failing set, the first and the last date, the number of trees, and if a clean record of a commit on the default branch is one of them.

Order of run_on. Refuse a tree that is not clean (exit 2). Probe and print the load and the free memory. Ask have, make a bundle of the commit without the commits that the gate clone holds, recv. Stop with no record when the reported commit is not the sent commit or the tree was not clean. start. Poll status; while the state is queued, print who holds the lock and since when, one time for each change. On done: fetch the JUnit tar, record with the label of the gate machine and gate_machine=True, print the end of the log, cleanup, return the exit code of exit.json. Rules of the driver. A lock is the folder full-gate.lock, made with one mkdir, with a file that names the run, the PID and the start time. A holder whose PID is not alive is released.
