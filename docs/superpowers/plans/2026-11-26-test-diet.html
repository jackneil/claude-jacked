What the second review found in these tasks

  1. prove can prove nothing and still write a proof: a patch that breaks the build, a subject command that always fails, a patch that changes nothing, an environment that is broken before the patch, an exit code that is missing, or a proof record that a hand wrote.
  2. prove works in the present worktree. When it stops between the patch and the reverse, the planted defect stays in the tree.
  3. A wrong test selector (pytest exit code 5, no test ran) reads as "the test caught the defect".
  4. The baseline is not tied to the tree and the gate command of the ledger.
  5. An approval is a plain field. The terminal check has a way around it. An approval and a proof are not bound to the content of their row.
  6. The detector for protected tests does not read the guardrails file and does not find a test that a rule names by its function.
  7. The ledger has no field for the tree before and after each batch.
  8. The signals of loss are in no step of the skill and not in the report.
  9. The control group for the saving can hold tests that the run made faster through a shared fixture, and its formula is not defined.
  10. A cut of kind duplicate or dead-target needs no mechanical check.

Both reviewers said the same thing about the limit of this design: no local command can stop a record that a model writes by hand. So each check is worth the careless error that it catches, and no more. The first version of this plan added commands as if they could do more.

Goal

Ship a gate recorder (jacked tests) and a skill (/test-diet) in claude-jacked, for Claude Code and for Codex. The recorder measures each gate. The skill uses those records to make a repository's test suite smaller and faster on a branch, with a proof for each cut, and opens a pull request.

The gate machine (jacked tests run --on) is in the gate machine plan, which is on hold.

Spec: 2026-11-25-test-diet-design.html (approved by the owner on 2026-11-26). Research: 2026-11-25-test-suite-diet-research.html. The executor reads both.

Tech stack: Python 3.11+ (requires-python of this package), click, pytest. No new third-party package.

Architecture

One new package, jacked/testdiet/, holds the mechanical work: it reads JUnit XML, gives each tree an identity, keeps a local history, runs a planted-defect proof, and compares test IDs with a ledger. One new skill directory holds the judgment as guidance for a model. The skill calls the commands. The commands never decide that a test is junk.

Global constraints

Each task's requirements include this section.

  • No third-party package in jacked/testdiet/. Use the helpers that jacked has, and do not write them again: jacked.atomic_io.atomic_write_bytes (atomic_io.py:332) for each file of the history, the ledger and the report; jacked.packs.jacked_home (packs.py:97); jacked.git_guard.run_git and guarded_git_env for a git read that needs no filter; jacked.findbin.find_bin; jacked.regular_file.open_regular_fd for each path that a caller gives; jacked.skill_listing.parse_frontmatter and _truthy for frontmatter.
  • Each child process is an argument list. No shell=True.
  • No module name starts with test_ in the package, and no class name starts with Test.
  • The history holds IDs, numbers, states and the class name of a failure. No failure message, no test output, no log text, no command text (only its SHA-256). It is in the common git directory of the clone and git never commits it.
  • A value that a file does not hold stays empty (None, null). It is never zero.
  • jacked tests run returns the exit code of the command that it wraps. A recorder error never changes that code. The one exception is the flag --strict.
  • Times of two machines are never compared. A machine is its label and a local fingerprint.
  • No committed file holds a host name, an address, a user name or a home path. Tests and documents use the label shed and the host gate.example.
  • A test ID is free text. Escape it in HTML. Remove control characters, except the newline and the tab, before a print to a terminal. A label matches [A-Za-z0-9._-]+.
  • No arbitrary threshold decides a verdict. A command prints numbers. It does not call a test slow, junk or flaky.
  • The skill text is guidance for a model. No point tables, no regular expressions that give a verdict. A name or a text pattern only nominates a test.
  • The new skill has no <!-- ENGINE --> marker and has disable-model-invocation: true.
  • Documentation, docstrings and user-visible messages are in ASD-STE100. No em-dash in them.
  • Sample reports come from real runs. The capture script changes only the host name and the root path. Nobody edits a report by hand.
  • A test name in this plan is a requirement. The test asserts what its name says, with the values of the rules of its task. A task can add tests. It does not drop one.
  • The suite runs on Linux, macOS and Windows in hosted CI (.github/workflows/tests.yml). Write text files as bytes or with newline="". A value that a system does not give is empty there.
  • Tests: uv run python -m pytest <files>. Each task runs its own test files plus grep -rl <changed module or directory name> tests/. The full suite runs one time, in Task 16. Each task reports --durations=10 of its new test files.
  • Process rule, verbatim in each brief: NEVER pkill -f / killall a generic pattern (pytest, python, node, a server name) on this machine; stop only processes you started, by PID.
  • Load: run uptime before each test run. Above a load of 15 on this machine, run the targeted files with no parallel workers and say so.

Review focus

  1. The gate writes no JUnit file, an old one, or half of one. Expected: the exit code comes back unchanged, the record has no test data and can never satisfy seen, and an old file is never read as this run. Tests in Task 3.
  2. The gate script exits 0 and the JUnit file holds failures (a pipe, or || true). Expected: a conflict, printed, never a pass. Tests in Task 3.
  3. The tree changes while the gate runs, has changes that are not committed, or the gate writes its own output into the tree. Expected: seen never says yes for a tree that did not run, and a tree that changed is named. Tests in Tasks 2 and 3.
  4. Several sessions finish a gate in the same second. Expected: each record is complete. Test in Task 2.
  5. A ledger row whose claim is false: a cut with no keeper, a "covered" cut whose keeper does not catch the defect, a faster test that no longer catches it, a cut of a test that failed in the baseline. Expected: ledger verify refuses each one. Tests in Tasks 6 and 8.
