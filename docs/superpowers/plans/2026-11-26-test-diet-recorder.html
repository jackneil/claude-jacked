Goal

Ship the gate recorder: the command group jacked tests with run, record, seen, profile, history, prune and loss. The recorder measures each gate of a repository and keeps a local history. A session can ask seen before it starts a full gate, and a tree that passed does not run again. This plan also repairs the Codex policy file for the two user-only skills that jacked ships today.

Spec: 2026-11-25-test-diet-design.html (approved by the owner on 2026-11-26), Part 1 and Part 3. Research: 2026-11-25-test-suite-diet-research.html. The executor reads both.

Tech stack: Python 3.11+ (requires-python of this package), click, pytest. No new third-party package.

Architecture

One new package, jacked/testdiet/, holds the mechanical work: it reads JUnit XML, gives each tree an identity, and keeps a local history. The commands print numbers. They never decide that a test is slow, junk or flaky.

flowchart LR
    CLI[jacked tests: cli.py group] --> REC[record.py: run, record, seen]
    CLI --> VIEW[views.py: profile, history]
    CLI --> LOSS[loss.py: loss report]
    REC --> JU[junit.py + ids.py]
    REC --> TREE[tree.py: tree identity]
    REC --> HIST[(history.py: git common dir)]
    VIEW --> HIST
    LOSS --> GIT[(git)]

Global constraints

Each task's requirements include this section.

  • No third-party package in jacked/testdiet/. Use the helpers that jacked has, and do not write them again: jacked.atomic_io.atomic_write_bytes (atomic_io.py:332) for each file of the history; jacked.packs.jacked_home (packs.py:97; it is the home folder, and jacked keeps its state in .claude/ under it); jacked.git_guard.run_git for a git read that needs no filter; jacked.findbin.find_bin; jacked.regular_file.open_regular_fd for each path that a caller gives.
  • Each child process is an argument list. No shell=True.
  • No module name starts with test_ in the package, and no class name starts with Test.
  • The history holds IDs, numbers, states and the class name of a failure. No failure message, no test output, no log text, no command text (only its SHA-256). It is in the common git directory of the clone and git never commits it.
  • A value that a file does not hold stays empty (None, null). It is never zero.
  • jacked tests run returns the exit code of the command that it wraps. A recorder error never changes that code. The one exception is the flag --strict.
  • Times of two machines are never compared. A machine is its label and a private random identity.
  • No committed file holds a host name, an address, a user name or a home path. A sample report holds the host gate.example and the root /work.
  • A test ID is free text. Remove control characters, except the newline and the tab, before a print to a terminal. A label matches [A-Za-z0-9._-]+, checked with re.fullmatch.
  • No arbitrary threshold decides a verdict. A command prints numbers.
  • Documentation, docstrings and user-visible messages are in ASD-STE100. No em-dash in them.
  • Sample reports come from real runs. The capture script changes only the host name and the root path. Nobody edits a report by hand.
  • A test name in this plan is a requirement. The test asserts what its name says, with the values of the rules of its task. A task can add tests. It does not drop one. When a real report contradicts a rule of this plan, the report is right: stop and report.
  • The suite runs on Linux, macOS and Windows in hosted CI (.github/workflows/tests.yml). Write text files as bytes or with newline="". A value that a system does not give is empty there.
  • This suite guards real processes. Read the exec guard and the markers real_process and real_process_tree in tests/conftest.py before you write a test that starts git or a child process, and follow a present test that does the same (tests/unit/test_git_reality.py).
  • Tests: uv run python -m pytest <files>. Each task runs its own test files plus grep -rl <changed module or directory name> tests/, and uv run ruff check on the files that it changed. The full suite runs one time, in Task 11. Each task reports --durations=10 of its new test files.
  • Process rule, verbatim in each brief: NEVER pkill -f / killall a generic pattern (pytest, python, node, layout_qa.py, ci_local.py --layout, a server name) on this machine; stop only processes you started, by PID.
  • Load: run uptime before each test run. Above a load of 15 on this machine, run the targeted files with no parallel workers and say so.

Review focus

  1. The gate writes no JUnit file, an old one, or half of one. Expected: the exit code comes back unchanged, the record has no test data and can never satisfy seen, and an old file is never read as this run. Tests in Task 3.
  2. The gate script exits 0 and the JUnit file holds failures (a pipe, or || true). Expected: a conflict, printed, never a pass. Tests in Task 3.
  3. The tree changes while the gate runs, has changes that are not committed, or the gate writes its own output into the tree. Expected: seen never says yes for a tree that did not run, and a tree that changed is named. Tests in Tasks 2 and 3.
  4. Several sessions finish a gate in the same second. Expected: each record is complete. Test in Task 2.
  5. The same gate runs a second time, and its report goes to a new folder. Expected: one command SHA for both runs, and seen says yes. Tests in Task 3.

SubjectDecisionReason
History formatTwo files for each run in <git common dir>/jacked-tests/runs/: <id>.tests.json.gz first, then <id>.meta.json. The meta file is the commit marker: a run with no meta file does not exist. The ID is <UTC time>-<8 random hex>.No shared file, so parallel sessions cannot damage a record.
RetentionNothing is deleted automatically. history --size prints the size. jacked tests prune --before DATE deletes on request and prints each deleted run.An automatic limit drops data silently.
Tree identityTreeId(commit, tree, clean). A clean tree uses HEAD^{tree}. A tree with changes uses a copy of the index (git rev-parse --git-path index) and a temporary object directory (GIT_OBJECT_DIRECTORY, with the real one in GIT_ALTERNATE_OBJECT_DIRECTORIES), then git add -A and git write-tree. Each git call has GIT_OPTIONAL_LOCKS=0. The real index and the real object store do not change. The clean and smudge filters stay on, because the hash must be equal to the tree of a commit. A repository with no commit, or a bare one, has no tree.Two commits with the same content are one tree. Changes that are not committed are in the identity.
Limits of the identityIt does not hold a file that git ignores, and it does not hold a change inside the work tree of a submodule. --input GLOB adds a fingerprint of named files (path, size, modification time in nanoseconds, not content) to the record and to seen. With git-lfs, the clean filter can write a copy of a new large file into the lfs folder of the clone. The reference text says these limits.In the owner's data service a stale ignored file changed the result of a gate.
The gate command and the report pathThe record holds command_sha: the SHA-256 of the arguments as the caller typed them, joined by a NUL. An argument can hold the text {junit}. Then run makes a private folder with tempfile.mkdtemp, puts <folder>/junit.xml in place of each {junit}, reads that file after the gate, and removes the folder before it reads the tree a second time. seen hashes the same typed command. --kind full|targeted is a label for the views only.A label that the caller picks cannot prove which command ran. A path that changes for each run must not be in the hash.
A report at a fixed path--junit GLOB, one or more times, for a runner that writes its report where its own configuration says. Before the run, the recorder takes the SHA-256 of the content of each match. After the run it reads a match that is new or whose content changed, and prints one line for each match that it did not read.A clock or a coarse file system must not hide a fresh report. An old report must not become this run.
Verdict of a runpassed: exit code 0, a JUnit file was read, no failed and no error test, at least one test. failed: exit code not 0. conflict: exit code 0 and a failed or an error test. no-data: exit code 0 and no JUnit data, or no test in it. unknown: no exit code (a record with no --exit-code).A pipe can turn a red gate into exit code 0.
One ID two timesOne CaseResult for each ID. attempts counts the attempts that the report shows. The seconds are the sum. The state is flaky when one attempt passed and one attempt failed or had an error. If not, it is the worst state (error, failed, passed, skipped). A flaky test is not in the failing set. If the real report of a rerun tool does not show the first attempt, the state is the state that the report shows, and the task report says so.A rerun tool can write one test more than one time.

def private_hits(text: str, *, host: str, login: str, home: str) -> list[str]

Rules of the reader. Open each path with open_regular_fd. Parse with xml.etree.ElementTree.XMLParser(target=T) and feed the file in blocks. T.start reads the attributes that the fields need. T.data does nothing, so the reader never holds the text of an element. T.doctype raises JUnitError. A ParseError becomes a JUnitError. No size limit. The message attribute of a failure element goes into no field.

Rule of private_hits. It returns each private value that the text holds. The home path matches as text, with either separator. The host name (the full name and its first part) and the login name match as a whole word: the character before and the character after are not a letter, a digit or an underscore. The match ignores case. The capture script calls it with the values of the machine that captures, and stops when it returns a hit.

Rules of run. The order is: read the tree; hash the typed command; make the report folder when an argument holds {junit}; start the child; wait; read the report; remove the report folder; read the tree a second time; write the record. The child inherits standard output and standard error. The record holds the tree identity from before the child. When the two identities differ, tree_changed is true and run prints the changed paths. After an interrupt of the parent, run waits for the child. A child that a signal stops gives 128 plus the signal number. A command that cannot start gives 127. Outside a git repository, run runs the command, prints one line, records nothing and returns the exit code. On a conflict it prints one line on standard error that says that the gate returned 0 and that the report holds failures; with --strict it returns 1.

Rule of seen. It returns a run only when all of these are true: source is run; verdict is passed; tree_changed is false (not empty); the tree hash, the command SHA and the inputs fingerprint are equal; the machine identity is equal and not empty, unless --any-machine.

Rule of the notice. It states facts: how many earlier records hold the same failing signature, the first and the last date, the number of trees, and how many of those records have on_default_branch true. It does not say whose defect it is.
