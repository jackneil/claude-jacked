Findings

[cve][CRITICAL] SCSC-001: 139 known advisories in the locked dependency set

Status: fixed

Evidence: osv-scanner on master's uv.lock: pillow 12.2.0 (up to CVSS 9.8, fix 13.0.0), anyio 4.13.0 (CVSS 9.3), certifi 2026.4.22 (CVSS 9.1), aiohttp 3.13.5 (up to 8.7), starlette 1.0.0 (up to 7.5), multidict 6.7.1 (5.3). Scorecard Vulnerabilities: 85 existing.

Risk: An attacker could send crafted input to a vulnerable aiohttp/starlette code path (the service is an HTTP server and an HTTP client), or exploit pillow image decoding, on every install built from this lock.

Fix: Targeted upgrade of the six packages under a cutoff moved to 2026-10-22: aiohttp 3.14.5, anyio 4.14.2, certifi 2026.10.19, multidict 7.1.0, pillow 13.0.0, starlette 1.9.0 (yarl 1.25.1 follows aiohttp). Pillow cap raised to <14. Pillow 13 needs Python 3.11, and Python 3.10 reached end of life in October 2026, so requires-python is now >=3.11. After: osv-scanner 'No issues found'; pip-audit (osv and pypi databases) 'No known vulnerabilities found'.

[lockfile][HIGH] SCSC-002: The exclude-newer cooldown was five months behind

Status: fixed

Evidence: pyproject.toml [tool.uv] exclude-newer = 2026-05-13. The cooldown is meant to delay a new release by about seven days; left in place it froze every security fix out of the lock.

Risk: An attacker could keep exploiting a fixed vulnerability for months, because the build refuses every release newer than the cutoff, including the fix.

Fix: Cutoff moved to 2026-10-22 (seven days before the audit), with a comment that a stale cutoff is its own risk.

[lockfile][HIGH] SCSC-003: starlette had no upper version bound

Status: fixed

Evidence: pyproject.toml: "starlette>=0.48" (16 prod deps, only this one unbounded).

Risk: An attacker who publishes a poisoned starlette 99.0 could land it in any downstream fresh resolve, whatever this repo's lock says.

Fix: "starlette>=0.48,<2".

[actions-hardening][HIGH] SCSC-004: CI tool installs were not hash-pinned

Status: fixed

Evidence: Scorecard Pinned-Dependencies 5/10: pipCommand not pinned by hash at tests.yml:41 (uv) and publish.yml:32-33 (pip, build, hatchling, cyclonedx-bom, twine).

Risk: An attacker who compromises one of those PyPI projects (or a transitive dependency) could run code in the publish job, the job that holds the PyPI OIDC token.

Fix: New .github/requirements/ci-uv.txt and ci-publish.txt (from .in files, uv pip compile --universal --generate-hashes, same cutoff); workflows install with --require-hashes --only-binary=:all:. Rehearsed locally on Python 3.11: hashed install, python -m build, twine check PASSED (wheel and sdist), cyclonedx-py SBOM 78 KB. osv-scanner on both files: no issues.

[actions-hardening][HIGH] SCSC-005: install.sh piped a remote installer to sh

Status: fixed

Evidence: install.sh:13 curl -LsSf https://astral.sh/uv/install.sh | sh (Scorecard downloadThenRun not pinned).

Risk: An attacker who controls or compromises that URL could run any code on the machine of everyone who runs the jacked installer.

Fix: The script no longer runs another installer: it prints the official uv install command and exits, which matches the README's 'install uv first' step (the script already asked the user to re-run it after installing uv).

[lockfile][MEDIUM] SCSC-006: Dependabot never updated uv.lock

Status: fixed

Evidence: .github/dependabot.yml used package-ecosystem "pip" for a uv project; its PRs (#122pr anthropic, #177pr ruff) changed pyproject.toml only, while CI runs uv run --frozen from uv.lock.

Risk: An attacker benefits when security updates are proposed but never reach the locked build: a merged Dependabot PR looks like a fix and changes nothing.

Fix: package-ecosystem "uv" for the project (7-day cooldown kept), plus a pip entry for .github/requirements.

[lockfile][MEDIUM] SCSC-007: An unused runtime dependency (anthropic)

Status: fixed

Evidence: pyproject.toml declared anthropic>=0.40,<1; no file in the repository imports it (jacked calls the API with httpx).

Risk: An attacker who compromises the anthropic SDK or one of its four exclusive transitive dependencies gains code execution in every jacked install, for code jacked never uses.

Fix: Removed; the lock drops anthropic, distro, docstring-parser, jiter and sniffio. #122pr is superseded.

[precommit][MEDIUM] SCSC-008: Lint was not enforced in CI

Status: fixed

Evidence: tests.yml ran pytest only; a lint regression (E702 in tests/unit/api/test_db_off_loop_guard.py) reached master.

Risk: Not an attack path by itself; it removes a guard that catches unsafe patterns before review.

Fix: tests.yml runs uv run --frozen ruff check . before pytest; the rule set is pinned in [tool.ruff.lint] so a ruff upgrade cannot change it (ruff 0.15 and 0.17 both report 0 findings). #177pr is superseded by the pinned rules plus the <0.18 cap.
