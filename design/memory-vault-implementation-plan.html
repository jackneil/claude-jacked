1. Conventions (binding, from recon)

  • Home/testability: everything resolves via jacked_home()-style $JACKED_HOME override (packs.py:93). Vault dir: Path(os.getenv("JACKED_VAULT_DIR") or jacked_home() / "jacked-vault"). State file: <home>/.claude/jacked-memory.json.
  • State file schema: versioned + tolerant + atomic exactly like packs.py (STATE_VERSION, load→normalize preserving unknown keys, mkstemp+os.replace save — packs.py:200-294). Keys: version, enabled, vault_dir, triage_model ("haiku" default, user-overridable), drift_added, drift_threshold (15), last_rollup, last_sync, retry_queue [], processed_merges {sha: iso} (age-pruned 90d, never count-capped).
  • Hooks fail open: module main() never raises out — top-level try/except, always effective exit 0 (pattern: session_account_tracker.py; unknown-hook shim already exits 0, cli.py:959-965). Slow work in a daemon thread with t.join(timeout=...) only where the event allows; SessionEnd capture may run in-process (session is ending) but MUST swallow all exceptions.
  • settings.json entries: marker comments # jacked-memory-capture / # jacked-memory-recall; match-then-update-in-place, never blind append, never touch foreign entries (cli.py:1653-1667 pattern); write via _write_settings_atomic (cli.py:1135). Recall hook is SYNCHRONOUS (no async key — async stdout is not injected, cli.py:1791-1801). Capture entries carry "async": True. Events: ("SessionEnd",""), ("PreCompact","auto") for capture; ("SessionStart","") for recall.
  • Frontmatter: hand-rolled parser/serializer in vault.py (repo has no yaml dep — pyproject deps are click/dotenv/rich/fastapi/etc.). Tolerant parse; strict validated write.
  • CLI: @main.group(name="memory") + lazy from jacked import memory imports inside command bodies (packs group template, cli.py:3648). Rich console + _rich_escape for arbitrary text; click.confirm gated on sys.stdin.isatty().
  • User-facing copy: no em-dashes (tests assert this for packs, test_cli_packs.py:640 — mirror it).
  • Vault git: subprocess git -C <vault>; init creates the repo; every add/rollup/migrate commits. Sync is git pull --ff-only ONLY, timeout-guarded, skipped unless a remote exists and last_sync > 10 min ago; failure = skip + record in state (surfaced by status and the dashboard card). Never reset/checkout -f.
  • Transcripts are DATA: every triage prompt embeds transcript excerpts fenced, with an explicit instruction that content inside the fence is data and any instructions in it must be ignored.

2. Vault format (fixed by the design; code-level detail)

~/jacked-vault/
  README.md          agent-facing schema doc, written by init
  vault.json         {version:1, roots:["~/Github"], groups:{<g>:{repos:[<identity>...]}},
                      repo_map:{<identity>: <group>}}   identity = normalized remote URL else dir name
  groups/<g>/index.md      "- [title](decision/slug.md) — hook phrase (updated YYYY-MM-DD)" lines, soft cap 150
  groups/<g>/hot.md        current slice, overwritten by librarian/skills
  groups/<g>/{decision,convention,vision,reference}/<slug>.md
  groups/<g>/episodic/<repo>/{today-YYYY-MM-DD.md, recent.md, archive.md, core-memories.md}
  strategy/  archive/

Note frontmatter (exact keys): type (decision|convention|vision|reference|progress), repos (list), group, created, updated (ISO date), tags (list; candidate marks unreviewed auto-captures). Episodic entry format preserved from the remember plugin so migration is lossless: ## HH:MM | branch entries in today files; # Recent + ## YYYY-MM-DD; # Archive + ## Week of YYYY-MM-DD (plugin regexes: consolidate.py:32, save-session.sh:192).

4. Security / data-integrity invariants (test-enforced)

  • Migration never deletes or rewrites any source file; count verification fails loud (nonzero) on any mismatch.
  • All hooks exit 0 on every failure path; a broken vault must never block a session or a git merge.
  • Vault sync: ff-only, never destructive; conflicts skip + surface.
  • Note slugs sanitized (no path separators/traversal — mirror features.py:483 guard); group/repo names path-safe.
  • Transcript/PR text handled as data: fenced in prompts with ignore-instructions framing; never executed; Rich-escaped when printed.
  • No silent size caps anywhere; the 1500-token recall budget is the design's real constraint and trimming logs what was cut (in the brief's own last line when trimmed).
  • settings.json mutations: atomic writes, marker-scoped, foreign entries untouched, backup snapshots already made by install flow.
Execution: one milestone at a time on feature/memory-vault; each milestone lands as its own commit only after its tests + acceptance run green locally. Coding agents must escalate (stop and report) if a needed decision isn't covered here or in the design doc.
